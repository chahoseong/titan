# PROJECT.md

Titan 프로젝트의 목적, 방향, 범위를 정의한다.
구현 방향을 판단할 때 이 문서를 기준으로 삼는다.

## 1. 목적

게임플레이 시스템을 직접 설계하고 구현한 과정과 결과를 보여 주기 위한 포트폴리오 프로젝트다.

## 2. 방향

여러 콘텐츠를 넓게 만들기보다 보스전 하나를 깊이 있게 완성한다.
프로젝트의 중심은 거대 보스와의 전투이며, 다른 요소는 모두 이 전투를 뒷받침하기 위해 만든다.
기능을 넣을지 판단할 때는 보스전에 기여하는지를 기준으로 삼는다.

## 3. 게임 컨셉

인간 크기의 보병이 거대한 2족 보행 메크 보스와 싸우는 3인칭 슈팅 게임이다.

- 플레이어는 보스의 부위를 골라 공격한다
- 부위가 파괴되면 보스의 행동과 약점이 달라진다
- 보스는 체력과 부위 상태에 따라 페이즈가 바뀐다

## 4. 범위

### 포함

| 영역 | 내용 |
|---|---|
| 플레이어 캐릭터 | 이동, 조준, 회피, 카메라 |
| 전투 | 무기, 데미지 처리, 부위별 피격과 파괴 |
| 보스 | 1종. 페이즈, 공격 패턴, 부위 상태에 따른 행동 변화 |
| 보스 애니메이션 | 기존 애니메이션 재생과 절차적 보정의 혼합 |
| 스테이지 | 1개 |
| UI | HUD, 보스 상태 표시 |
| 패키징 | 단독으로 실행되는 빌드 |
| 플랫폼과 입력 | Windows, 키보드와 마우스 |

### 제외

- 멀티플레이
- 여러 종류의 적을 전제로 한 공용 구조
- 여러 스테이지와 캠페인 진행
- 성장 요소: 인벤토리, 장비 강화, 레벨, 메타 진행
- 게임 출시: 스토어 등록과 배포

## 5. 단계

현재 단계: **1단계**

모든 단계는 패키징된 빌드, 시연 영상, 기술 문서로 끝난다.

### 1단계. 코어 루프

| 항목 | 내용 |
|---|---|
| 목표 | 보스전 한 판이 처음부터 끝까지 성립한다 |
| 방향 | 모든 요소를 가장 단순한 형태로 먼저 연결한다. 개별 요소의 깊이는 다음 단계로 미룬다 |

완료 기준

- 플레이어가 이동하고 조준해 보스를 공격할 수 있다
- 보스가 플레이어를 공격한다
- 맞힌 부위에 따라 보스가 받는 피해가 달라진다
- 보스를 쓰러뜨리면 승리하고 플레이어가 쓰러지면 패배한다

### 2단계. 시스템 깊이

| 항목 | 내용 |
|---|---|
| 목표 | 플레이어가 어느 부위를 공격하는지에 따라 보스전의 전개가 달라진다 |
| 방향 | 전투와 보스의 행동이 서로 영향을 주는 구조에 집중한다. 콘텐츠의 양보다 시스템 사이의 연결을 우선한다 |

완료 기준

- 보스의 부위를 파괴할 수 있다
- 부위가 파괴되면 보스의 행동이 달라진다
- 보스가 페이즈에 따라 다른 공격을 한다
- 플레이어가 보스의 공격을 미리 알아채고 피할 수 있다

### 3단계. 완성도

| 항목 | 내용 |
|---|---|
| 목표 | 처음 보는 사람이 설명 없이 끝까지 플레이할 수 있다 |
| 방향 | 새로운 시스템을 추가하지 않는다. 이미 있는 것을 다듬는다 |

완료 기준

- 패키징된 빌드에서 시작부터 승패까지 중단 없이 진행된다
- 보스의 체력과 부위 상태를 화면에서 알 수 있다
- 공격과 피격에 이펙트와 사운드가 있다

## 6. 미결 사항

| 항목 | 잠정안 | 결정 시점 |
|---|---|---|
| 자동화 테스트 범위 | 데미지 처리 단위 테스트 | 1단계 중 |
| 보스 AI 도구 | State Tree 또는 Behavior Tree | 2단계 시작 전 |
| 스테이지 구성 | 미정 | 3단계 시작 전 |
